# Goal(Codexのgoalモードにそのまま貼る) — 納品版(X)

## ゴール
原宿3LDKの試作CG(W版)から、**納品版(X)** を作る。作業範囲は次の5項目で、すべてユーザー承認済み。
1. ダイニングテーブルを、キッチンアイランドに詰める。
2. 2枚目の Eames の影を弱め、背面に回り込む光を足す。
3. ソファ(1枚目、3枚目)の面ごとの陰影と革の質感を強める。
4. 2枚目と5枚目の建築の合わせ込みを再調整する。
5. 4枚目の床の青みのうち、CGが足した反射による分を抑える。
W版の合成精度(床の反射・接地・既存反射の遮蔽・粒状感)は、下げない。

## 入力
- W版一式(zip、約204MB): https://www.icloud.com/iclouddrive/0910DVhboO0lM1qijhLsI9ZPA
  - 取得できない場合は、下の「取得方法」を試す。それでも無理なら、作業を止めて、その旨を `report.md` に書く(推測で進めない)。
- 重要ファイル: `source/Harajuku_LDK_W.blend`(約134MB)、`layout.json`、`revision_QA.json`、`details/contact_coverage.json`、`details/camera_fit_unchanged_from_V.json`、`07_plan.png`、`README.txt`。
- 取得方法(iCloud共有リンク):
  1. `POST https://ckdatabasews.icloud.com/database/1/com.apple.cloudkit/production/public/records/resolve`
     本文 `{"shortGUIDs":[{"value":"0910DVhboO0lM1qijhLsI9ZPA"}]}`
  2. 応答の `rootRecord` 配下にある `downloadURL` の `${f}` をファイル名に置換して GET。
- Blender が環境にない場合は、インストール可否を確認し、できなければ停止して報告する。

## 配置変更の仕様
- 動かすのは、Linha Dining(テーブル)と、Torii 6脚だけ。
- テーブルの、キッチン側の短辺の端を、アイランド側の端に接触させる(隙間ほぼ0)。
- 現状は、テーブル端〜カウンター端が約420mm空いている(赤線の位置)。
- テーブルの向き(角度)はアイランドと平行でないため、そのまま平行移動するとくさび形の隙間ができる可能性がある。
  - その場合は、「アイランドの端面に、テーブルの短辺を正対させる」向きに、テーブルを回転する。
  - 回転が必要になったら、どの角度に何度動かしたかを `report.md` に記録する。
  - 椅子6脚は、テーブルに対する相対位置を保つ。
- 窓側の椅子3脚が、窓ガラスやマリオンに干渉する場合は、テーブル全体を窓から離す方向へ補正する。補正量を記録する。
- テーブルの長さ(2600mm)や素材は変えない。

## 各項目の仕様
**項目2(Eames)**: 影を物理的に弱くする(周囲の既存の影と同程度の濃さ・柔らかさ)。背面が一様に暗くならないよう、窓外からの回り込みの光を足す。W版の補修済みサーフェスは変えない。
**項目3(ソファ)**: マテリアルとライティングで行う(後処理のレタッチは不可)。面ごとの明暗差、窓側は暖色寄り・日陰側は冷色寄り、3枚目の座面上面への緑の映り込み、縫い目の陰影、革の微細な反射を入れる。
**項目4(合わせ込み)**: 2枚目(u2)と5枚目(p13)だけ、カメラを再調整してよい。背景写真は変えない。建築側のRMS誤差(原寸px)を W版(21.0 / 16.8)より下げ、目標は 7px 以下。他の3視点のカメラは W版と同一。再調整後の値を `camera_fit_X.json` に出す。
**項目5(床の青み)**: CG反射の強さ・色を調整し、家具から離れた床の平均色が元写真と一致するようにする。家具近くの反射は残す。元写真は変えない。

## 変えてはいけないもの
背景写真(未加工)、ライト(項目2の回り込み光の追加を除く)、テーブルと椅子6脚以外の家具の位置と向き、u1・p09・p01 のカメラ。 `AGENTS.md` の「絶対に守る」を参照。

## 作業手順
1. 入力を取得し、`sha256sum` を記録する。
2. 変更前の状態(カメラ5つ、家具の位置と回転、ライト)をJSONで書き出す。
3. 変更を、次の順で入れる(1つ終えるごとに、プレビューを保存)。 配置(`layout.json` はテーブル+椅子のみ更新、`07_plan.png` も更新) → Eames → ソファ → u2・p13 のカメラ → 床の青み。
4. 5視点を、W版と同じ設定で再レンダリング(床反射・遮蔽・接地AO・粒状感・周辺部のにじみのパス構成も同じ)。
5. `ACCEPTANCE.md` のチェックをすべて実行する。
6. 結果を `report.md` にまとめる(数値、差分、失敗したチェックはそのまま)。

## 完了条件
`ACCEPTANCE.md` の全項目が合格し、`out_X/` に所定のファイルがすべて揃っている。1つでも不合格なら「完了」としない。原因と、残った差分を書いて止める。(目標値に届かない項目は、実測値と理由を書き、レビュー担当に判断を委ねる)

## 止める条件(推測で進めない)
- 入力が取得できない、または sha256 が想定と違う。
- テーブルをアイランドに詰めると、椅子や窓に干渉し、仕様の補正だけでは解消できない。
- 背景写真、または u1・p09・p01 のカメラを変えないと再レンダリングできない。
- W版の合成精度を再現できない(`contact_coverage.json` の基準を満たせない)。
→ 状況を `report.md` に書いて、ユーザーに確認を求める。

## 報告のルール
- 合成精度と、上の5項目の変更内容だけを書く。権利、予算、サイト、配置の是非などの意見は書かない。
- 5項目以外で気づいた点は、`report.md` の末尾に「未対応の観察」として、1〜3行で添えるだけにする(直さない)。
